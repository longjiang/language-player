# ADR-0025: Web Framework — Next.js 14 App Router → Next.js 16.3 (Turbopack + React 19.2)

**Date**: 2026-08-04
**Status**: accepted
**See also**: [ADR-0002 (Next.js App Router)](0002-nextjs-app-router.md), [ADR-0001 (Monorepo Tooling)](0001-monorepo-tooling.md), [SPEC-002 (Repository Migration)](../specs/002-repo-migration.md)

## Context

`apps/web` is the greenfield replacement for the Nuxt 2 Classic app. It was
originally scaffolded on **Next.js 14 (App Router, React 18)**. The choice of
the framework itself was recorded only implicitly:

- **ADR-0002** documents App Router over Pages Router, noting App Router became
  stable in Next.js 14. Its rationale — React Server Components, nested
  layouts, streaming, `loading.tsx`/`error.tsx`, Metadata API, and a greenfield
  rewrite with no migration cost — is why Next.js (rather than Nuxt 2 or the
  Pages Router) became the web stack.
- **SPEC-002** and ROADMAP treat "Next.js 14, Tailwind, shadcn/ui" as the
  scaffold without a separate version-rationale record.
- **ADR-0001** chose Turborepo + npm workspaces, which hoists shared
  dependencies to the workspace root.

By August 2026 the Next.js 14 line is the legacy path: `next dev` and
`next build` default to webpack, React 18 is two majors behind, and several
App Router APIs have moved (`middleware.ts` → `proxy.ts`, sync
`params`/`searchParams` → async). The Classic replacement work is feature-rich
enough that the web app is the live product, so staying on 14 means carrying a
webpack-only configuration and an aging React version forward.

## Decision

**Upgrade `apps/web` to Next.js 16.3 with React 19.2 and make Turbopack the
default bundler for both dev and build.**

1. **Dependencies**: `next@^16.3.0`, `react@^19.2.8`, and
   `react-dom@^19.2.8`. React is hoisted to the workspace root (root
   devDependencies), and `apps/mobile` is aligned to the same 19.2.8 so web and
   mobile share one hoisted copy with no duplicate React trees.
2. **Bundler**: remove `--webpack` from `dev`/`build` scripts and drop the
   custom `webpack()` chunk-merging config. Next 16's Turbopack pipeline handles
   code splitting; the webpack-specific tuning does not apply.
3. **API migrations required by Next 16**: `middleware.ts` → `proxy.ts`;
   `params`/`searchParams` are async Promises in layouts, pages, and routes;
   ESLint flat config (`eslint.config.mjs`); `next-intl` upgraded to `^4.13.5`.
4. **Type/React alignment**: `@types/react`/`@types/react-dom` overridden at the
   root, and a `touchTimer` typing fix in `use-selection-popup.ts` exposed by
   the newer React types.
5. **Workspace hygiene**: `apps/mobile-go-legacy` is excluded from npm
   workspaces (`!apps/mobile-go-legacy`) — it is no longer built or installed.
6. **Build checks stay dev-safe**: Next 16 isolates dev and build outputs
   (`.next/dev` vs `.next/build`) but shares `.next/cache`, so running a build
   next to a live dev server contends on the Turbopack cache. `build:check`
   therefore builds into an isolated `.next-check` via
   `BUILD_CHECK=1` + `distDir`, and `scripts/build-check.mjs` restores
   `next-env.d.ts` (which Next rewrites to the active `distDir`) and cleans up
   afterwards.

## Consequences

### Gained

- Turbopack is the default for dev and production builds: faster compiles and
  no webpack configuration to maintain. `npm run build:check -w apps/web`
  completes in ~13s for the full route set.
- React 19.2 across web and mobile from one hoisted copy; `npm ls` is clean and
  typecheck passes for all packages.
- The app is back on the supported Next line, with access to current App Router
  features and bug fixes.
- The legacy GO app is out of the workspace, so hoisting can no longer conflict
  with or install it.

### Accepted

- The old `webpack()` splitChunks tuning is gone; if Turbopack ever produces
  problematic chunk splits, the fix is Turbopack config, not a webpack
  function.
- The dev server must be restarted after the upgrade to pick up Turbopack (a
  running server started with `--webpack` stays on webpack until restarted).
- `next-env.d.ts` is mode-dependent: dev rewrites it to `.next/dev`, build to
  `.next` (or `.next-check` for build checks). It is regenerated by Next and
  should not be edited by hand.
- `--webpack` remains available as a temporary escape hatch, but it is not part
  of the normal scripts.

## Alternatives considered

1. **Stay on Next.js 14 + React 18**: rejected — the web app is the live
   product and 14 is the legacy path; webpack-only config and React 18 would
   keep accruing migration cost and missing App Router fixes.
2. **Upgrade to Next.js 15 first, then 16 later**: rejected — 15 is a
   waypoint, and the async-params/`proxy.ts`/Turbopack work is required for 16
   anyway; one jump avoids doing the same migration twice.
3. **Next.js 16 with `--webpack` retained**: rejected — Turbopack is the
   default and verified working for this app; keeping webpack would preserve
   config that no longer matches the supported path.
